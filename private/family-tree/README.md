# Family Tree

Family Tree — настольное приложение для построения и изучения семейной родословной. Дерево редактируется на свободном холсте, а сведения о людях, связях и расположении карточек хранятся локально в SQLite. Фотографии и документы лежат отдельными файлами в рабочем каталоге дерева.

Это описание отражает реализованное состояние приложения, а не весь набор таблиц схемы или будущие пункты меню.

## Возможности

### Семейное дерево и холст

- Большой свободно перемещаемый холст: перетаскивание пустой области двигает представление, колесо мыши меняет масштаб относительно курсора.
- Масштаб от 5% до 2000%; есть быстрый переход к 100% и команда показа всего дерева.
- Карточки имеют размер `250 × 350 px`. Координата `x` задаёт левую границу карточки, `y` соответствует центру поколения.
- Карточки выравниваются по поколениям; при размещении и перемещении проверяется пересечение карточек и минимальный горизонтальный зазор.
- Можно выделять одну или несколько карточек, перемещать их как группу, фиксировать карточки и задавать защищённые области холста.
- Доступны вспомогательные линии поколений и межпоколенческие направляющие; их видимость настраивается.
- Команда центрирования показывает дерево целиком, а выравнивание не должно менять взаимное расположение карточек.
- Перемещения, блокировка, добавление и некоторые изменения данных поддерживают отмену через `Ctrl+Z` / `Cmd+Z`. В интерфейсе также доступен список людей для перехода к нужной карточке.

### Люди и карточки

У человека можно хранить:

- имя, отчество, фамилию и прежнюю фамилию;
- пол и гендерную идентичность;
- даты рождения и смерти;
- фотографию с настройками кадрирования, масштаба и положения фокуса;
- национальность, этническую принадлежность, религию, профессию и образование;
- описание, биографию и исследовательский статус.

Редактирование разделено на краткую и расширенную формы. Карточка показывает портрет и основные сведения; для умершего человека отображается траурный визуальный маркер. Поддерживаются светлая и тёмная темы.

### Связи

Поддерживаются два вида связи:

- **Брак** — пара людей, состояние (действующий или расторгнутый), сведения о регистрации и расторжении, заметки, документы и фотография пары.
- **Родительская связь** — родитель и ребёнок, роль родителя и параметры размещения/выравнивания семьи.

Связи можно создавать выбором карточек, редактировать, удалять и перемещать вместе с соответствующими карточками. Для браков предусмотрены отдельные варианты визуального обозначения, в том числе расторгнутого брака и предыдущего брака с умершим супругом. Для родительских связей доступны авторазмещение семей и ручное перемещение линий/узлов с проверкой конфликтов.

### Обслуживание дерева

- **Корзина** позволяет восстановить удалённого человека или удалить его данные окончательно.
- Настройки включают выбор каталога дерева, импорт/экспорт, управление защищёнными областями, тему интерфейса, вспомогательные линии и опасные действия.
- Очистка дерева и удаление связей требуют отдельного подтверждения.
- При переносе рабочего каталога приложение готовит копию и проверяет базу до переключения на новое место.

### Импорт и экспорт

Поддерживаются следующие форматы:

| Формат | Импорт | Экспорт | Состав |
| --- | --- | --- | --- |
| JSON | Да | Да | Люди, их основные данные, позиции и поддерживаемые связи; основной формат полного обмена |
| CSV | Да | Да | Табличные данные людей; связи не включаются |
| GEDCOM 7 | Да | Да | Данные людей |
| GEDCOM 5.5.1 | Да | Да | Данные людей |

Для импорта доступны режимы **«Объединить»** и **«Заменить»**. При объединении приложение пропускает обнаруженные дубликаты, а для замены запрашивает дополнительное подтверждение.

## Рабочее пространство и хранение данных

Приложение работает с одним активным локальным деревом. При первом запуске используется каталог данных приложения; для дерева создаётся следующая структура:

```text
FamilyTree/
└── <Название дерева>/
    ├── db/
    │   └── family-tree.sqlite3
    └── media/
        └── <ID человека>/
            ├── profile/
            └── documents/
                ├── birth/
                ├── death/
                ├── marriage/
                ├── residence/
                ├── military/
                └── other/
```

Путь активной базы записывается в `workspace.json` в каталоге данных приложения. Если сохранённый путь больше не указывает на существующий файл базы, приложение открывает рабочее дерево по умолчанию.

SQLite хранит сведения о людях, имена, события рождения и смерти, связи, координаты карточек и метаданные медиа. Содержимое фотографий и документов не встраивается в базу: файлы лежат в каталоге `media`, а записи базы связывают файлы с соответствующими сущностями. Кадрирование портрета и фото пары сохраняется как PNG.

При обычном удалении человек скрывается из активного дерева и попадает в корзину. Восстановление возвращает его в дерево; окончательное удаление также удаляет принадлежащий человеку каталог медиа.

Формат каталога переносим вместе с подкаталогами `db` и `media`. Рекомендуется закрыть приложение перед ручным копированием или резервированием этих данных. Экспорт в JSON — отдельный способ обмена данными и не заменяет копию каталога с медиафайлами.

## Ограничения

- Идентификаторы людей выдаются автоматически в формате `P0001`–`P9999`. Последовательность не переиспользует номера удалённых людей; после исчерпания диапазона создавать новых людей нельзя.
- Размер файла импорта ограничен 100 МБ.
- GEDCOM и CSV в текущем импорте/экспорте предназначены для обмена данными людей. Связи экспортируются в полном JSON-формате.
- Автоматизированный облачный аккаунт, синхронизация между устройствами и серверное хранилище в текущей реализации не предусмотрены.

Других прикладных лимитов на число карточек, поколений или размер дерева в интерфейсе не задано. Фактическая вместимость зависит от доступного места на диске и ресурсов компьютера.

## Технологии и архитектура

### Клиентская часть

- **React 19** и **TypeScript** — интерфейс и типизированные модели.
- **Vite** — dev-сервер и сборка web-части.
- **Zustand** — состояние карточек, связей, выделения и истории отмены.
- **CSS** и **Tailwind CSS** — стили приложения.
- **Tauri API и плагины** — вызовы Rust-команд, системные диалоги выбора файлов, файловые операции и открытие ссылок.

Компонент `Canvas` координирует холст и модальные формы; специализированные хуки отвечают за панорамирование/масштабирование, выделение области, перетаскивание и контекстные меню. Геометрия карточек и связей вынесена в функции `src/lib/canvas`.

### Системная часть

- **Tauri 2** создаёт настольное приложение и связывает UI с Rust.
- **Rust** реализует операции с рабочим каталогом, медиафайлами, импортом/экспортом и SQLite.
- **rusqlite** работает с локальной SQLite-базой; миграции хранятся в `src-tauri/migrations`.
- Команды, доступные интерфейсу, регистрируются в `src-tauri/src/lib.rs`; основная работа с данными находится в `database.rs`, форматами обмена — в `transfer.rs`.

Вызовы из клиентского кода проходят через `invoke`. Модель интерфейса преобразуется в записи базы и обратно в `src/store/canvasPersistence.ts`. Схема содержит также задел под источники, цитаты, факты и заметки; наличие таблицы само по себе не означает, что соответствующий сценарий полностью доступен в пользовательском интерфейсе.

## Структура проекта

```text
src/
├── components/       # Холст, карточки, меню, формы и модальные окна
├── hooks/            # Общие React-хуки
├── lib/
│   ├── app/          # Вспомогательные функции приложения
│   ├── canvas/       # Геометрия, раскладка и логика связей
│   └── person/       # Логика данных человека
├── store/            # Состояние и синхронизация с backend
└── types/            # TypeScript-модели

src-tauri/
├── migrations/       # SQL-схема и миграции SQLite
└── src/
    ├── database.rs   # Рабочее пространство и операции с данными
    ├── geometry.rs   # Геометрия на стороне Rust
    ├── transfer.rs   # Импорт и экспорт
    └── lib.rs        # Сборка приложения и регистрация команд Tauri
```

## Разработка и сборка

### Требования

- Node.js с пакетным менеджером **pnpm**;
- Rust toolchain, Cargo и компоненты, необходимые Tauri 2 для целевой ОС;
- для Windows-сборки — поддерживаемая среда Windows-разработки, необходимая Tauri.

### Команды

```powershell
pnpm install
pnpm tauri dev
```

`pnpm tauri dev` запускает приложение в режиме разработки вместе с Vite.

```powershell
pnpm build
pnpm tauri build
```

`pnpm build` проверяет TypeScript и собирает frontend. `pnpm tauri build` формирует настольный пакет для настроенной платформы.

Проверка Rust backend:

```powershell
cargo check --manifest-path src-tauri/Cargo.toml
cargo fmt --manifest-path src-tauri/Cargo.toml --check
```

Версии frontend-зависимостей зафиксированы lock-файлом `pnpm-lock.yaml`. Для сборки Tauri запускается frontend-команда `pnpm build`.
