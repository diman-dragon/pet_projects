# Lumen — просмотр фото и видео на уровне файлового менеджера

Быстрый и аккуратный просмотрщик медиа для Android. Capacitor + TypeScript (без UI-фреймворков) и один нативный плагин на Java для MediaStore.

## Что умеет

- **Фото** — лента по дням, виртуальная сетка (десятки тысяч файлов без лагов), быстрая прокрутка с подписью месяца.
- **Альбомы** — папки с файлами, обложка = последний снимок.
- **Папки** — настоящее дерево: вложенные папки, количество файлов и размер.
- **Избранное**, **корзина** (30 дней, восстановление / удаление навсегда).
- **Просмотрщик** — свайп между файлами, pinch-зум и double-tap, закрытие свайпом вниз, видео, информация (EXIF, камера, GPS, путь).
- **Операции** — выделение долгим тапом и протяжкой, переместить / копировать / переименовать / поделиться / в корзину, создание новых папок.
- Сортировка (дата / имя / размер), фильтр фото/видео, поиск по имени и папке, скрытие папок.
- Темы: системная, тёмная, светлая, AMOLED. Языки: русский, английский.
- Новые снимки подхватываются сами (ContentObserver).

## Как собрать APK — только VS Code + git

1. Создайте репозиторий на GitHub и запушьте проект:
   ```bash
   git init && git add . && git commit -m "Lumen"
   git branch -M main
   git remote add origin <url> && git push -u origin main
   ```
2. GitHub Actions (`.github/workflows/android.yml`) сам соберёт APK. Скачайте его на вкладке **Actions → последний запуск → Artifacts → lumen-apk**.
3. Для релиза: `git tag v1.0.0 && git push --tags` — APK появится в Releases.

### Подпись

Ключ `signing/lumen.jks` лежит в репозитории и используется при каждой сборке, поэтому APK обновляются поверх друг друга. Пароли в `.github/workflows/android.yml`. Это ключ для разработки: перед публикацией в магазин создайте новый и храните его в секретах.

## Разработка в браузере

```bash
npm install
npm run dev
```

Без Android включается мок-библиотека (≈2800 файлов с градиентами) — можно отлаживать весь интерфейс в Chrome (DevTools → режим телефона). Колесо мыши — зум, стрелки — листание, Esc — назад.

## Локальная сборка (если когда-нибудь поставите Android SDK)

```bash
npm install
npm run android:prepare   # web build + cap add android + патч + cap sync
npm run android:apk       # android/app/build/outputs/apk/debug/
```

## Устройство проекта

```
src/
  main.ts       запуск, кнопка «назад», подписки
  views.ts      экран: вкладки, сетка, выделение, настройки, корзина
  viewer.ts     полноэкранный просмотрщик с жестами
  vlist.ts      виртуальный список + быстрая прокрутка
  thumbs.ts     загрузка миниатюр (очередь, события из нативного слоя)
  store.ts      библиотека, индекс папок, избранное, настройки
  actions.ts    операции: удалить, переместить, переименовать, инфо, выбор папки
  native.ts     мост к плагину + мок для браузера
  i18n.ts       ru/en
native/android/java/com/lumen/gallery/MediaLibraryPlugin.java
scripts/setup-android.mjs   патчит сгенерированный android/ (плагин, разрешения, иконка, minSdk)
```

`android/` не хранится в git — его генерирует `cap add android`, а `scripts/setup-android.mjs` докладывает плагин, разрешения (`READ_MEDIA_*`, `ACCESS_MEDIA_LOCATION`, `MANAGE_MEDIA`), иконку и ставит `minSdk 30`.

### Как это быстро работает

- Список файлов читается одним проходом MediaStore и отдаётся в JS порциями по 6000 — первая лента появляется до конца чтения.
- Миниатюры делает система (`ContentResolver.loadThumbnail`), кэшируются в WEBP; очередь LIFO — сначала то, что на экране сейчас.
- В DOM — только видимые строки сетки; полноразмерные файлы идут напрямую через `_capacitor_content_` без копирования.

## Права и поведение на Android

- Android 13+: `READ_MEDIA_IMAGES/VIDEO`; 11–12: `READ_EXTERNAL_STORAGE`. Выбор «только некоторые фото» (Android 14) не поддерживается — нужен полный доступ.
- Изменение чужих файлов (перемещение, переименование, корзина) на Android 11+ требует системного подтверждения. В **Настройки → Операции без подтверждений** можно выдать `MANAGE_MEDIA` — тогда окон не будет (удаление навсегда подтверждается всегда).
- MediaStore ограничивает, в какие папки можно класть фото и видео (обычно `DCIM/`, `Pictures/`, `Movies/`; на части версий Android — и `Download/`). Если система откажет, приложение покажет причину.
